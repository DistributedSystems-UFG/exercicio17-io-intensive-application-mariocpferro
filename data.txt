Java is a high-level, class-based, object-oriented programming language.
Concurrency is the ability of a program to be decomposed into parts that can run out of order.
A thread is the smallest unit of processing that can be performed in an operating system.
Thread pools reduce the overhead of thread creation by reusing a fixed set of threads.
The Java Virtual Machine schedules threads for execution on available processors.
File I/O involves reading from or writing to persistent storage devices such as disks.
Buffered I/O improves performance by reducing the number of system calls required.
A server socket listens on a port and accepts incoming client connections.
TCP provides reliable, ordered, and error-checked delivery of data between applications.
When a thread performs blocking I/O, it releases the CPU allowing other threads to run.
Race conditions occur when multiple threads access shared data without synchronization.
Synchronization primitives include mutexes, semaphores, and monitors.
A deadlock occurs when two or more threads are blocked forever waiting for each other.
ExecutorService is a Java interface that provides methods to manage thread pools.
Callable and Runnable are interfaces used to define tasks executed by threads.
Future represents the result of an asynchronous computation in Java.

AtomicInteger provides atomic operations on integer values without explicit synchronization.
Volatile ensures visibility of variable changes across threads in Java.
Thread-local storage provides each thread with its own independent copy of a variable.
The happens-before relationship defines the ordering guarantees between thread operations.
Amdahl's Law describes the theoretical speedup of a program using multiple processors.
Context switching is the process of saving and restoring the state of a thread or process.
Operating systems use scheduling algorithms to determine which thread runs next.
Round-robin scheduling assigns equal time slices to all ready threads in cyclic order.
Priority-based scheduling allows higher-priority threads to preempt lower-priority ones.
Non-blocking I/O allows a single thread to handle many connections simultaneously.

Queue theory helps analyze waiting times and resource utilization in concurrent systems.
Little's Law relates throughput, latency, and the number of concurrent requests in a system.
Benchmarking measures the performance characteristics of a system under controlled conditions.

JIT compilation improves runtime performance by compiling bytecode to native machine code.
The JVM warm-up period refers to the time before JIT optimizations take full effect.
Memory-mapped files allow large files to be accessed as if they were in memory.
The page cache in the OS caches recently accessed disk blocks in RAM for faster access.

SSD storage offers much lower read latency compared to traditional spinning hard drives.
RAID configurations can improve disk throughput by striping data across multiple drives.
Database connection pools reuse connections to avoid the overhead of establishing new ones.

Transactions provide atomicity, consistency, isolation, and durability in database operations.
Optimistic locking assumes conflicts are rare and checks for them only at commit time.

Eventual consistency allows distributed systems to remain available despite temporary inconsistencies.

Sharding partitions data across multiple nodes to distribute load and increase capacity.
Message queues decouple producers and consumers and buffer messages during peak load.

Canary releases gradually roll out changes to a small subset of users before full deployment.
Feature flags enable or disable features at runtime without deploying new code.
